# Contributing to Yunto

> **Internal only** — this guide is for authorized Yunto employees and contractors.

## Getting Started

1. Clone the repository and follow the setup instructions in [README.md](./README.md)
2. Check the [Linear project](https://linear.app/yunto/project/yunto-33c165e2) for available tasks
3. Create a feature branch from `main`

## Branch Naming

Use the branch name generated by Linear when picking up an issue:

```
vedant/yun-42-build-real-time-messaging-system
```

Format: `<name>/yun-<issue-number>-<short-description>`

## Commit Messages

Follow [Conventional Commits](https://www.conventionalcommits.org/):

```
feat(frontend): add login page with email/password flow
fix(backend): resolve token refresh race condition
chore: update dependencies
```

**Prefixes:** `feat`, `fix`, `chore`, `refactor`, `test`, `docs`, `style`, `perf`, `ci`

**Scopes:** `frontend`, `backend`, `shared`, `infra`, `prisma`

## Pull Requests

1. Create a PR against `main`
2. Fill out the PR template
3. Ensure all checks pass (lint, typecheck, tests)
4. Request review from @vedantpatnaik

### PR Title Format

```
feat(frontend): build leads pipeline page UI
```

## Code Standards

- **TypeScript** — strict mode, no `any` types
- **Frontend** — React functional components, Tailwind for styling, shadcn/ui components
- **Backend** — Express route handlers, Prisma for DB access, Zod for validation
- **Shared** — Zod schemas in `packages/shared` for both frontend and backend

### File Organization

- One component per file
- Co-locate tests with source files (`Component.tsx` + `Component.test.tsx`)
- Use barrel exports (`index.ts`) for module public APIs

## Design Implementation

- All UI must match the [Figma designs](https://www.figma.com/design/KC4ItIHV2hSpevWxXCHMG4)
- Use the project's design tokens (cream/beige palette)
- Responsive: desktop (1024px+), tablet (768px), mobile (390px)

## Questions?

Reach out on Slack in `#dev-general` or tag @vedantpatnaik on the relevant issue.
